    19. Fallstudie – Version 1

    19.1. Die simulierte Schicht [metier]

    Kommen wir noch einmal auf die Architektur der Anwendung zurück, die wir entwickeln:

    Wir verfügen über das Archiv der Schichten [metier, dao, jpa] und haben die Elemente dieser Schichten vorgestellt, die die Schicht [web] kennen muss. Wir sind bereit, diese mithilfe des Struts-Frameworks zu schreiben.

    Um das Testen unserer in der Entwicklung befindlichen Anwendung zu vereinfachen, werden wir eine simulierte Geschäftsschicht erstellen, die die Schnittstelle der Schicht [metier] erfüllt. Die Architektur wird wie folgt aussehen:

    Wir werden die Schicht [web] zusammen mit der simulierten Schicht [métier] entwickeln. Die Tests lassen sich einfacher durchführen, da in der Architektur keine Datenbank mehr vorhanden ist. Dank Spring und der Verwendung von Schnittstellen wird das spätere Ersetzen der simulierten Schicht [metier] durch die echte Architektur [metier, dao, jpa] keinerlei Auswirkungen auf den Code der Schicht [web / struts2] haben. Die Schicht [web / struts2], die wir nun entwickeln werden, kann unverändert verwendet werden.

    Die simulierte Schicht [metier], die wir verwenden werden, lautet wie folgt:

      listEmployes.add(new Employe("260124402111742", "Laverti", "Justine", "La br�lerie", "St Marcel", "49014", new Indemnite(1, 1.93, 2, 3, 12)));

<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE struts PUBLIC

    "http://struts.apache.org/dtds/struts-2.0.dtd">

<struts>
  <!-- Internationalisierung -->
  <constant name="struts.custom.i18n.resources" value="messages" />
  <!-- Spring-Integration -->
  <constant name="struts.objectFactory.spring.autoWire" value="name" />

  <package name="default" namespace="/" extends="tiles-default">
    <!-- Standard-Aktion -->
    <default-action-ref name="index" />

      </result>

    • Zeile 10: Legt fest, wie Spring-Beans in Struts-Aktionen injiziert werden. Die Injektion erfolgt anhand des Namens des Beans. Das Feld der Struts-Aktion, das von Spring initialisiert werden soll, muss denselben Namen wie das zu injizierende Bean tragen.

<struts>

...
public class Supprimer extends ActionSupport implements SessionAware {

  // Sitzung
  private Map<String, Object> session;
  // ID der zu löschenden Simulation
  private String id;
  // Menü
  private Menu menu;

  @Override
  public void setSession(Map<String, Object> session) {
    this.session = session;
  }

  // Ausführung der Aktion
  public String execute() {
    // Die Simulationen werden aus der Sitzung abgerufen
    List<Simulation> simulations = (List<Simulation>) session.get("simulations");
    if (simulations == null) {
      // Ausnahmefall – die Sitzung ist abgelaufen
      menu = new Menu(false, false, false, false, true, true);
      return "erreur";
    }
    // ID-Prüfung
    int num = 0;
    boolean erreur = false;
    try {
      num = Integer.parseInt(id);
      erreur = num <= 0;
    } catch (NumberFormatException ex) {
      // Fehler
      erreur = true;
    }
    // Fehler?
    if (erreur) {
      menu = new Menu(false, false, false, false, true, true);
      return "erreur";
    }
    // Die zu löschende Simulation wird gesucht
    for (int i = 0; i < simulations.size(); i++) {
      if (num == simulations.get(i).getNum()) {
        simulations.remove(i);
        break;
      }
    }
    // Liste der Simulationen wird angezeigt
    menu = new Menu(false, false, false, false, true, true);
    return "simulations";
  }

  // Getter und Setter
...
}
